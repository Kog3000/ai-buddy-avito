# AI-buddy — ИИ-наставник для стажёров

Прототип для кейса Авито на Hack&Change 2026. AI-buddy помогает стажёру освоиться в команде: отвечает на вопросы
по базе знаний с учётом команды и этапа адаптации, оформляет заявки в корпоративных сервисах (доступы, отгул,
встреча с наставником), показывает этапы адаптации и следующие шаги, а вопросы без ответа передаёт наставнику
и пополняет ими FAQ.

> Все данные и инструкции синтетические. Тестовые материалы **не являются регламентами Авито**.

## Быстрый старт

### Вариант 1. Docker (PostgreSQL)
```bash
cp .env.example .env        # необязательно: без файла работают значения по умолчанию
docker compose up --build
```
Откройте http://localhost:8000. Поднимаются `app` (Flask + gunicorn), `db` (PostgreSQL 16) и `cron` (имитация ИИ-крона).

### Вариант 2. Локально (SQLite)
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
python wsgi.py              # http://localhost:8000, БД и тестовые данные создаются при старте
```
Сбросить данные: удалить `instance/ai_buddy.db` и перезапустить.

### Роли
- **Стажёр** — чат с AI-buddy, чек-лист, база знаний, прогресс и цели, наставник (встречи, заметки), «Доступы и отгулы».
- **Наставник** — помогает с задачами и адаптацией каждый день: «Стажёры», «Встречи» (подтверждает приглашения),
  «Вопросы стажёров» (ответы → FAQ), «AI-ассистент» (сводка по стажёрам, повестка 1:1, встречи на подтверждении).
- **Руководитель** — отвечает за команду и проекты, а не за ежедневное сопровождение: ставит цели на испытательный
  срок (организаторы: цели ставятся с руководителем на первой неделе), согласует отсутствия, владеет проектами —
  поэтому согласует доступы с правами на редактирование. Наставник не может согласовать отгул или выдать доступ.
- **Куратор стажировки (админ)** — заводит кабинеты, выдаёт временные пароли, закрепляет наставника и руководителя,
  отключает кабинеты. Новый стажёр сразу получает чек-лист и (по галочке) добавляется в обязательные каналы.

## Как проверить (≈7 минут)
1. **`arina` → Главная.** Прогресс 3 из 28 (11%), следующие шаги, наставник. Совпадает с макетами.
   В «Чек-листе» — 5 этапов по срокам из чек-листа стажёра Авито: неделя 1, неделя 2, месяц 1, месяцы 2–3, после 3 месяцев.
2. **Чат → «Где хранятся документы нашей команды?»** Ответ из базы знаний со ссылками на источники.
3. **«Помоги настроить доступы к основным сервисам» → «Отправить все заявки».** В сервис доступов уходят 4 заявки.
   Через ~8 с VPN и Confluence одобряет политика — в чат приходят сообщения о выдаче.
4. **«Как оформить отгул?» → «В пятницу» → «Отправить заявку».** Процедура, проверка правил, заявка руководителю.
5. **«Запланируй встречу с наставником»** → слот → повестка собрана из твоих вопросов → «Запланировать».
   Или **Наставник → «Запланировать встречу»**: календарь на 4 недели с общими свободными окнами. Встреча ждёт
   подтверждения; `ivan` подтверждает её в разделе **«Встречи»**, стажёр получает уведомление, а задача
   «Назначить регулярные встречи 1:1 с наставником» закрывается сама.
   **«Добавь меня во все нужные чаты»** — AI-buddy добавляет в обязательные каналы команды и потока.
   **Скрепка в чате** — прикрепить лог или скриншот (до 5 МБ) и передать наставнику вместе с вопросом.
6. **«Сколько стоит обед в столовой?»** Ответа в базе нет, AI-buddy предлагает передать вопрос → «Передать наставнику».
7. **Выйти → `maria` → Согласования.** Согласовать Stash, Jira и отгул. **Метрики** → feature flags.
8. **`ivan` → Вопросы стажёров.** Ответить с галочкой «Добавить в FAQ».
9. **`arina` → колокольчик и Чат.** Пришли уведомления и ответ наставника, решения по заявкам. Задача «Настроить доступы…» закрыта с пометкой
   «отмечено AI-buddy». Повторный вопрос про обед теперь закрывается из FAQ без наставника.
10. **`elena` → Пользователи → «Создать кабинет».** Логин и временный пароль показываются один раз;
    «Закрепить» меняет наставника стажёра. Профиль любого пользователя редактируется карандашом.
11. **Права:** у `arina` нет доступа к `/approvals` и `/metrics`. На запрос «нужен доступ к продовой бд» заявка
    не создаётся, а материал «Шкала оценки стажёров» стажёру не показывается.

## Данные Авито, учтённые в прототипе
- **Доступы:** стажёр получает те же доступы, что и команда — Jira (бэклоги, тикеты), Confluence (спецификации, гайды),
  Stash (код сервисов команды), Redash и Grafana (продуктовые метрики). Данные по стратегии, финпоказателям и планам
  запусков — по заявке с указанием задачи. Ограничения задаются ресурсом (например, prod-БД — только у SRE),
  а не статусом стажёра.
- **Метрики** (страница «Метрики» у наставника и руководителя): базовые показатели онбординга (~2 недели до первой
  самостоятельной задачи, ~2 месяца адаптации, 9/10 онбординг, 68% чек-лист, 90% наставник, ~5 ч/нед наставника)
  рядом с целями прототипа; обращения разложены по пяти темам из статистики: организационные, по задачам,
  профессиональные, развитие, обратная связь.

## LLM (необязательно)
По умолчанию `LLM_PROVIDER=offline`: ответы собираются из найденных материалов, все сценарии работают без ключа.
Чтобы включить синтез ответов LLM, нужен любой OpenAI-совместимый Chat Completions API:

| Переменная | Пример | Назначение |
|---|---|---|
| `LLM_PROVIDER` | `openai` | включить LLM |
| `LLM_BASE_URL` | `https://api.openai.com/v1` | эндпоинт (OpenAI, OpenRouter, vLLM и т.п.) |
| `LLM_MODEL` | `gpt-4o-mini` | модель |
| `LLM_API_KEY` | `sk-...` | ключ (только через окружение / `.env`) |
| `LLM_TIMEOUT` | `25` | таймаут, с |

Если LLM недоступна или ответила с ошибкой, AI-buddy автоматически отвечает офлайн. Флаг `llm_answers` выключает
LLM без перезапуска.

## API
- `POST /api/chat/send` `{text}` или `{action, params, label}` → `202 {job_id}`; `GET /api/chat/jobs/<id>`
- `GET /api/chat/messages?after=<id>` — история и проактивные сообщения
- `POST /mcp` — MCP JSON-RPC (`initialize`, `tools/list`, `tools/call`) от имени текущего пользователя
- `POST /api/cron/run` с заголовком `X-Cron-Token` — задачи ИИ-крона
- встречи: `GET /api/meetings/availability`, `POST /api/meetings` (приглашение), `POST /api/meetings/<id>/decide`
  (наставник), `POST /api/meetings/<id>/cancel` (стажёр)
- каналы: `GET /api/chats`, `POST /api/chats/join`; вложения: `POST /api/chat/send` (multipart, поле `file`),
  `GET /api/attachments/<id>` (автор, его наставник и руководитель)
- куратор: `GET|POST /api/admin/users`, `/api/admin/users/<id>/assign|password|active`; профиль: `PUT /api/profile`
- остальное: `/api/checklist`, `/api/kb/search` (разделы + темы), `/api/requests`, `/api/approvals/*`, `/api/notes`,
  `/api/goals`, `/api/mentor/questions/*`, `/api/metrics`, `/api/flags`, `/api/notifications/read`
